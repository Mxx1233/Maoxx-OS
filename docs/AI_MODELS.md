# AI 模型策略

## 当前状态

当前尚未正式接入模型网关，机器人回复主要是固定逻辑。任何现有固定回复都不代表已具备意图识别、结构化提取或业务路由能力。

## 目标模型网关

- 所有模型调用统一经过 Model Gateway，业务服务不直接绑定供应商 SDK。
- 第一版先接入一个 OpenAI-compatible 模型，再扩展多 provider 和多模型路由。
- 普通分类、摘要和简单提取优先使用低成本模型。
- 复杂规划、框架设计和高难度推理可使用更强模型。
- 图片识别使用支持视觉输入的模型。
- 模型返回应尽量使用经过 schema 校验的结构化输出。
- 保存 `model_runs` 等调用元数据、耗时、状态、错误和用量，但不保存 API Key。
- 统一记录 token usage，并通过 `prompt_versions` 追踪 Prompt 版本。
- 必须支持超时、有限重试、降级、错误记录和可观测性。
- Prompt 需要版本化，输出必须能追溯模型、版本和输入来源。

## 数据责任

模型输出是候选数据，不是最终事实。正式业务写入必须通过字段校验、权限检查和所需的人工确认。发送给外部模型的数据遵循最小化原则，敏感模块需单独进行隐私评审。

API Key 只通过 `.env` 或后续受控秘密管理系统注入，不进入数据库、日志、Git 或文档。图片识别由支持视觉输入的模型承担，也必须经过相同网关、追踪和确认规则。
